# PCL: 같은 지급 요청의 허용·거부 비교

**분류: [Simulation] — 실제 Maroo 테스트넷 RPC에서 수행한 `eth_estimateGas`.** 서명·broadcast·정책 변경은 하지 않는다. 이 실험의 거부는 포함된 거래의 revert가 아니다. 별도의 [실제 1 tOKRW 송금](../../evidence/live-testnet/OKRW_TRANSFER_VERIFIED.json)이 Track B의 상태 변경 증거다.

## 왜 이 실험을 하는가

기업 지급 시스템은 송금 전에 금액·자격·정책 조건을 확인해야 한다. 단순히 PCL 주소를 조회하는 것보다, 같은 발신자와 수신자에서 **금액 하나만 바꿨을 때 실제 RPC의 판정이 달라지는지** 확인한다.

실험 계정의 실제 잔액 부족이 정책보다 먼저 실패하지 않도록 RPC의 state override로 잔액을 100,000,000 tOKRW로 가정한다. 실제 자금은 생성되거나 이동하지 않는다. 모든 케이스를 같은 블록에 고정하고 나머지 입력을 유지한다.

## 실행

Node 22와 의존성 준비 후 제출 저장소 루트에서:

```bash
node scripts/probe-pcl-estimation.mjs
```

개인키는 필요 없다. 스크립트에 명시한 공개 테스트 계정의 과거/현재 정책 효과를 조사하는 실습이다. 참가자 본인 계정으로 바꾸면 자격에 따라 결과가 달라질 수 있다.

## 확인한 결과

블록 19174089에서:

| 지급액(tOKRW) | 관찰한 RPC 결과 |
|---|---|
| 1 | 가스 추정 성공 |
| 2,000,000 | 가스 추정 성공 |
| 2,000,001 | `AnyOfRejected` |

거부 오류를 공식 ABI로 재귀 해석한 결과:

- `VolumeAboveMaxLimit`: 상한 2,000,000, 요청 2,000,001.
- `EasNoAttestationReceived`: 해당 발신자의 대체 자격 경로도 통과하지 못함.
- 하위 `AnyOfRejected` 안에서도 EAS 자격 부재가 확인됨.

[실행 증거](../../evidence/local/PCL_ESTIMATION_PROBE.json). 공개 정책 구조는 [기존 정책 해석](../../evidence/local/PCL_DECODED.json)과 비교한다. 두 자료의 블록은 다르므로 동일 시점 전체 정책 스냅샷이라고 주장하지 않는다.

## 성공 기준과 한계

세 케이스에서 한도 이하 통과와 초과 시 **명시적인 정책 오류**를 구분한다. RPC 장애나 잔액 부족을 정책 거부라고 세지 않는다. 정책 또는 계정 자격이 변경되면 스크립트는 예상 경계 불일치로 종료할 수 있다. 실행 시각·블록·오류를 다시 기록한다.

가스 추정 성공은 이후 broadcast 성공을 보장하지 않는다. 이 실험은 PCL을 RPC simulation에서 실제 평가한 증거이며, 관리자 권한·정책 변경·온체인 거부 거래·Privacy 정책 통과·법적 규제 준수를 증명하지 않는다. 한도 2,000,000은 모든 계정에 적용되는 절대 상한이라고 일반화하지 않는다. EAS 등의 OR 조건이 있기 때문이다.
