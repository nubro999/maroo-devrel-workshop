# EAS 정책을 해석할 때 주의할 점

워크숍의 기본 시나리오는 **미승인 → 승인 → 승인 취소**입니다. 이를 각각 **자격 증명 없음 → 유효한 증명 발급·인덱싱 → 기존 증명 폐기**로 표현합니다. 실제 결과는 차단 → 지급 성공 → 차단이었습니다.

## false를 넣으면 거절되는 정책인가요?

아닙니다. 추가 실험에서는 유효한 false 증명도 지급을 통과했습니다. 이번 EAS_POLICY 설정이 내부 bool 값의 true 여부를 강제하지 않았다는 뜻입니다. 이 사실은 정책을 잘못 해석하지 않도록 남긴 조사 결과이며, 워크숍의 기본 지급 시나리오는 아닙니다.

[실행 기록](../evidence/live-testnet/EAS_BOOLEAN_RESULT.json) · [독립 재조회](../evidence/live-testnet/EAS_BOOLEAN_VERIFIED.json)

approved=false일 때 차단하는 기능이 필요하다면 해당 데이터를 검사하는 정책 또는 계약 로직을 구현하고 별도로 검증해야 합니다. 현재 데모가 그 기능을 제공한다고 설명하지 않습니다.

## 실제 은행의 승인으로 사용하려면

승인된 대상에게만 증명을 발급하고, 승인을 취소하면 기존 증명을 폐기해야 합니다. 누가 해당 증명을 발급할 수 있는지도 통제해야 합니다. 이번 실습은 자체 발급 증명으로 수명주기를 확인했으며, 신뢰할 발급자 제한이나 실제 은행 KYB를 구현하지 않았습니다.

## 선택 실험

기본 수업 밖에서 정책의 데이터 검사 범위를 확인하고 싶을 때만 실행합니다. 테스트넷 수수료가 발생하며 먼저 PCL 실습을 완료해야 합니다.

```bash
node demo/pcl/eas-boolean.mjs --broadcast
```
