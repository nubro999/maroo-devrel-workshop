# 진행자 가이드

슬라이드는 10장입니다. 실습 명령은 [실습 웹사이트](https://maroo-workshop-cheatsheet.zcb167.chatgpt.site)로 분리했습니다. 은행 시스템 연결·Maroo 계층·프록시 호출·Privacy 구조는 다이어그램으로 설명합니다.

전체 진행 시간은 70분으로 계획했습니다. 참가자와 함께 시간을 측정한 리허설은 아직 하지 않았습니다. [참가자 시간표](PARTICIPANT_GUIDE.md)와 [슬라이드별 대본](Workshop_Speaker_Script.md)을 사용합니다. 프로그램 1(PCL·EAS)과 2(Privacy)는 별도 실행입니다. 별도 PoC 로드맵 강의는 없습니다.

## 준비

- D-1: Node/Go 버전, 개인별 테스트 자금, 새 프록시 실행, 로컬 build/artifact 완료 확인.
- PCL 정책 변경 권한은 각자가 배포한 프록시에만 사용합니다. Privacy 공용 정책이나 전역 정책은 변경하지 않습니다.
- 발급자 제한 없는 데모를 은행 KYB 인증으로 부르지 않습니다. 승인 상태를 증명 발급·폐기로 표현한다는 점을 설명합니다.
- 타임아웃 때 해시를 먼저 확인합니다. 참가자 키를 수집하지 않습니다.

## 진행 방식

15분까지 문제와 역할을 설명하고, 22분까지 프록시·Denylist 결과를 봅니다. 34분까지 EAS 수명주기를 실행하고 40분까지 폐기 후 차단과 정리 결과를 확인합니다. Privacy는 47분까지 구조를 설명하고 62분까지 로컬 실행, 마지막 8분은 증거 판독과 질문으로 마칩니다.

각 구간 종료 시 '성공 / 실패 / 미시도 / 기존 증거 분석'을 구분해 받습니다. 추가 bool 실험은 기본 수업에서 진행하지 않습니다. 질문이 나오면 정책 해석 주의사항으로 안내합니다.

## 장애 시 대체 진행

- RPC/환경 문제는 3분 이내 진단 후 제공된 실제 거래·JSON 분석으로 전환합니다. 당일 성공으로 표시하지 않습니다.
- 로컬 준비가 끝난 경우 프로그램 2를 먼저 진행할 수 있습니다.
- 로컬 실행이 불가능하면 LOCAL_PRIVACY_LIFECYCLE과 REHEARSAL을 분석하고 직접 실행 미완료를 기록합니다.
- 유효한 Maroo proof가 없으면 임의·0값 proof를 제출하지 않습니다.

## 질문과 기대 답변

- 승인 취소는 어떻게 반영하나? → 기존 증명을 폐기하고, 같은 지급 요청이 차단되는지 확인합니다.
- 거래 해시만 있으면 성공인가? → 블록 포함 여부, 실행 상태, 실제 잔액 변화를 함께 확인해야 함.
- Privacy가 누구에게 정보를 숨기나? → 공개 표면과 note 소유자·prover·감사 주체를 구분해야 함. 감사자 복호화 미검증.
- 오늘 검증하지 않은 것은? → 실제 KYB, 신뢰할 발급자 제한, Maroo Privacy 호환성, 운영 복구.

## 가스비를 설명할 때

참가자가 status 0을 보면 먼저 ‘의도한 정책 거절’인지 확인합니다. 지급되지 않은 0.001 tOKRW와 실패 거래에서 부과된 2.25 tOKRW를 나누어 설명하세요. 사전 시뮬레이션은 거래를 보내지 않지만 이번 데모는 실패 영수증까지 확인하려고 전송합니다. [설명과 실제 로그](../docs/GAS_AND_RESULTS.md)를 함께 보여주세요.
