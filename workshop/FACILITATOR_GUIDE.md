# 진행자 가이드

슬라이드는 10장입니다. 커맨드는 [실습 웹사이트](https://maroo-workshop-cheatsheet.zcb167.chatgpt.site)로 분리했습니다. 은행 시스템 연결·Maroo 계층·프록시 호출·Privacy 구조는 다이어그램으로 설명합니다.

70분은 설계값이며 전체 참가자 리허설은 미완료입니다. [참가자 시간표](PARTICIPANT_GUIDE.md)와 [슬라이드별 대본](Workshop_Speaker_Script.md)을 사용합니다. 프로그램 1(PCL·EAS)과 2(Privacy)는 별도 실행입니다. 별도 PoC 로드맵 강의는 없습니다.

## 준비

- D-1: Node/Go 버전, 개인별 테스트 자금, 새 프록시 실행, 로컬 build/artifact 완료 확인.
- PCL 정책 변경 권한은 각자가 배포한 프록시에만 사용합니다. Privacy 공용 정책이나 전역 정책은 변경하지 않습니다.
- 발급자 제한 없는 데모를 은행 KYB 인증으로 부르지 않습니다. false 실험의 해석을 확인합니다.
- 타임아웃 때 해시를 먼저 확인합니다. 참가자 키를 수집하지 않습니다.

## 진행 방식

15분까지 문제와 역할을 설명하고, 22분까지 프록시·Denylist 결과를 봅니다. 34분까지 EAS 수명주기를 실행하고 40분까지 false/true 차이를 해석합니다. Privacy는 47분까지 구조를 설명하고 62분까지 로컬 실행, 마지막 8분은 증거 판독과 질문으로 마칩니다.

각 구간 종료 시 '성공 / 실패 / 미시도 / 기존 증거 분석'을 구분해 받습니다. 빠른 참가자는 bool 실험을 직접 실행하고 다른 참가자는 실제 기록을 비교합니다.

## 장애 시 대체 진행

- RPC/환경 문제는 3분 이내 진단 후 제공된 실제 거래·JSON 분석으로 전환합니다. 당일 성공으로 표시하지 않습니다.
- 로컬 준비가 끝난 경우 프로그램 2를 먼저 진행할 수 있습니다.
- 로컬 실행이 불가능하면 LOCAL_PRIVACY_LIFECYCLE과 REHEARSAL을 분석하고 직접 실행 미완료를 기록합니다.
- 유효한 Maroo proof가 없으면 임의·0값 proof를 제출하지 않습니다.

## 질문과 기대 답변

- 왜 false도 통과했나? → 이번 EAS 조건이 bool true를 강제하지 않았기 때문. 승인 증명 발급·폐기 및 발급자 권한이 중요.
- 왜 hash만으로 성공인가를 말할 수 없나? → 포함·실행·상태를 확인해야 함.
- Privacy가 누구에게 정보를 숨기나? → 공개 표면과 note 소유자·prover·감사 주체를 구분해야 함. 감사자 복호화 미검증.
- 오늘 검증하지 않은 것은? → 실제 KYB, 신뢰할 발급자 제한, Maroo Privacy 호환성, 운영 복구.
