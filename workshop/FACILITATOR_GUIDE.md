# 진행자 가이드

상태: **70분 운영 설계 초안, 리허설 미완료**. Primary B의 완료 기준은 OKRW·PCL·Privacy의 의미 있는 연결과 증거이며, 현재 placeholder 실행만으로 충족하지 않는다.

## 사전 준비와 개최 판단

- [SETUP](SETUP.md)을 따라 새 소스·새 테스트 계정으로 참가자 온보딩을 리허설한다. 개발자의 기존 .env/캐시/artifact에 의존하지 않는다. 설치 안내, 실제 배포 URL, faucet 절차, 준비 시간은 리허설 후 확정한다.
- 참가자가 처음부터 설정할 수 있어야 한다. 설치를 행사에서 진행한다면 70분 본 실습 외 별도 setup 시간을 편성하고 안내한다. 아직 측정하지 않은 준비 시간을 보장하지 않는다.

- [참가자 가이드](PARTICIPANT_GUIDE.md)의 70분 시간표를 사용한다. 대상·역할은 [시나리오](../docs/SCENARIO.md)에서 조정한다.
- D-1: 깨끗한 환경에서 [검증 체크리스트](VALIDATION.md)를 수행하고 OS·Node·패키지 lock·Clairveil SHA를 기록한다.
- Clairveil checkout은 `.external/clairveil`에 분리한다. 빌드, circuit/artifact 다운로드, 테스트 계정 준비는 pre-work다. 검증하지 않은 prebuilt binary를 참가자에게 배포하지 않는다.
- 정확한 SHA에서 deposit → transfer → scan을 실행한 명령, 예상 출력, 초기화 방법을 demo/clairveil에 추가한다. 이것이 없으면 20분 privacy 실습의 준비 완료를 선언하지 않는다.
- 테스트넷 전용 자산을 준비하고 리허설 tx와 수신자 변화를 기록한다. 참가자 계정과 개인키를 중앙 문서에 모으지 않는다.
- [PCL 비교 실습](../demo/maroo/PCL_LAB.md)을 리허설한다. 실제 RPC simulation이며 balance override와 미전송 사실을 먼저 설명한다. 정책이 변경돼 예상 경계가 달라지면 새 결과를 기록하고 과거 증거와 비교한다. 포함된 거부 거래로 표현하지 않는다.
- 백업에는 정제된 **실제** 이전 실행 로그만 사용한다. 만들어낸 tx나 가공된 성공 출력은 준비하지 않는다.

## 구간별 진행 포인트

| 구간 | 진행자의 확인 | 토론/개입 |
|---|---|---|
| 0–8분 | live, local, docs-only 표기 | 공급업체 정보 중 숨길 대상과 감사자가 볼 대상은? |
| 8–18분 | chain ID와 계정/잔액 | HTTP 연결 성공과 올바른 체인 연결은 어떻게 다른가? |
| 18–30분 | dry run과 broadcast 구분 | tx hash, receipt, 상태 변화 중 무엇이 성공 증거인가? |
| 30–40분 | PCL 의사결정 지점·VP 누락 자료 | 조회만으로 정책 강제를 입증할 수 있는가? |
| 40–60분 | 같은 로컬 실행의 deposit/transfer/scan | prover·수취인·관찰자의 신뢰 경계는? |
| 60–70분 | 증거와 다음 PoC 목록 | production으로 가려면 누가 무엇을 추가 검증해야 하는가? |

각 구간 마지막 1분에 참가자가 성공/실패/미시도를 표시하게 한다. 한 사람의 개인키나 seed가 화면에 보이면 공유를 중지하고 해당 테스트 계정을 교체한다.

## 시간 제한과 장애 대안

RPC 장애는 재시도·대기만으로 3분 이상 소비하지 않는다. 최초 오류, 시간, 환경을 기록하고 실제 사전 실행 로그를 읽는 방식으로 전환한다. 이때 현재 참가자의 live 성공으로 표시하지 않는다. 정상 로컬 환경이 준비되어 있으면 privacy 실습을 먼저 진행하고 live는 이후 다시 시도한다.

Privacy 호환 artifact/query가 확인되지 않으면 추측하지 않고 로컬 reference로 이동한다. 로컬도 준비되지 않았으면 실제 기록 분석 또는 `[Simulation]` 상태 전이 토론으로 전환하고 미완료 항목을 남긴다. 시뮬레이션은 실제 end-to-end 재현을 완료했다고 인정하지 않는다.

정책 거부는 예상 입력과 정책 근거가 확인되어야 교육상 정상 거부로 분류한다. 임의 revert를 PCL 성공으로 해석하지 않는다. 원인별 확인은 [트러블슈팅](TROUBLESHOOTING.md)을 따른다.

## 종료·영상

개인키가 없는 증거만 취합하고, 참가자별 실행 여부를 [VALIDATION](VALIDATION.md)에 표시한다. 종료 후 권한 없는 반복 송금이나 자동 재시도를 남기지 않는다. 알려진 한계·DX 피드백을 SUBMISSION_NOTES에 반영한다.

Track B 영상은 5~8분으로 구성한다: 1분 문제·경계, 2분 실제 Maroo 시도와 판정, 2분 실제 로컬 privacy 재현, 1~2분 실패 계층·PCL·다음 단계. 실제로 하지 않은 구간은 미실행으로 명시한다.
