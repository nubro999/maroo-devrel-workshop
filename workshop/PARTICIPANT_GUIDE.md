# 참가자 실습 안내

현재 수업은 [직접 작성하는 터미널 실습](TERMINAL_LAB.md)을 따릅니다. [실습 사이트](https://maroo-workshop-cheatsheet.vercel.app)에서 같은 코드와 복사 버튼을 제공합니다.

| 직접 작성·조작 | 제공되는 준비 코드 |
|---|---|
| Solidity pay 함수: 권한·금액·송금·이벤트 | owner 초기화와 컨트랙트 골격 |
| PCL 정책 객체, selector, ABI 인코딩 | 공식 ABI와 RPC 연결 |
| EAS 스키마·증명·인덱싱·폐기 호출 | EAS 주소 조회와 ABI |
| 영수증·잔액·지급 횟수 검증 | 수수료 상한·전송 영수증 대기 도우미 |
| Privacy deposit·transfer·list-notes CLI와 잔액 assert | 노드 초기화·개발용 회로·prover·로컬 계정 |

아래 기존 자동 실행 안내는 리허설·참고용입니다. 수업의 기본 실행 경로는 위 터미널 실습입니다.

# 참가자 가이드

이 워크숍에서는 두 가지를 실행합니다. 먼저 Maroo에서 지급을 허용하거나 차단하는 정책을 확인합니다. 다음으로 별도 로컬 환경에서 비공개 지급을 보내고 받습니다.

## 준비

[사전 준비](SETUP.md)를 먼저 완료하세요. 설치·빌드·증명용 회로 준비는 70분 수업에 포함하지 않습니다. 자신의 테스트 계정을 사용하고, 개인키는 로컬 .env에만 입력합니다.

[커맨드 사이트](https://maroo-workshop-cheatsheet.zcb167.chatgpt.site)에서 명령을 복사할 수 있습니다. 사이트 접근이 제한되면 아래 명령과 연결된 공개 가이드를 사용하세요.

## 70분 진행 순서

| 시간 | 할 일 | 확인할 결과 |
|---|---|---|
| 0–15분 | 은행 승인과 체인 정책의 관계 이해 | 심사자·발급자·정책 관리자 역할 구분 |
| 15–22분 | 프록시 배포, 지급과 Denylist 차단 | 정상 status 1 / 차단 status 0 |
| 22–34분 | EAS 발급 전·후와 폐기 후 비교 | 거절 → 성공 → 거절 |
| 34–40분 | 승인 취소 후 차단 결과 확인 | 추가 지급이 없고 정책이 복원됐는지 확인 |
| 40–47분 | Privacy 구조와 공개 범위 이해 | 로컬 결과와 Maroo 결과 구분 |
| 47–62분 | 예치·비공개 지급·수신 조회 | Alice 3 / Bob 7, 반복 조회 일치 |
| 62–70분 | 결과와 오류 해석 | 직접 실행과 기존 증거 분석을 구분해 기록 |

## 실습 1. Maroo 지급 통제

저장소 루트에서 순서대로 실행하세요. PowerShell과 WSL 모두 아래 node 명령을 사용할 수 있습니다.

```bash
npm run check:rpc
npm run balance
node demo/pcl/run.mjs --broadcast
```

긴 로그에서는 normal-payment의 status 1, 수취인 증가량 0.001 tOKRW, blocked-state의 증가량 0을 먼저 보세요. 차단 거래의 status 0은 의도한 결과입니다. [로그·가스비 해설](../docs/GAS_AND_RESULTS.md)에 실제 예시가 있습니다.

프록시 실습이 성공하면 같은 프록시로 EAS를 확인합니다.

```bash
node demo/pcl/eas-run.mjs --broadcast
```

자격이 없으면 거절되고, 발급·인덱싱 후에는 지급되며, 폐기하면 다시 거절되는지 확인하세요. 자격은 자체 발급한 실습용이며 실제 은행 심사를 대신하지 않습니다.

여기서 미승인은 해당 자격 증명이 없는 상태, 승인은 유효한 증명을 발급·인덱싱한 상태, 승인 취소는 증명을 폐기한 상태입니다. [정책 해석 주의사항](../docs/POLICY_CAVEATS.md)은 기본 실습이 끝난 뒤 참고하세요.

## 실습 2. 로컬 Privacy

Linux/WSL2에서 [로컬 실행 안내](../demo/clairveil/LOCAL_RUN.md)를 따르세요. 고정한 소스와 개발용 증명 자료를 사용하고, 매번 새 실행 폴더를 만듭니다. artifacts 재사용만으로 Go 빌드 캐시까지 재사용되지는 않으므로 안내의 캐시 설정을 확인하세요.

PUBLIC_RESULT.json에서 다음을 확인합니다.

- 예치·준비 거래·최종 지급의 code가 모두 0입니다.
- Alice는 10에서 3으로 줄고, Bob은 0에서 7로 늘어납니다.
- Bob이 다시 조회해도 같은 결과가 나옵니다.

공유할 파일은 PUBLIC_RESULT.json입니다. 개인키·원시 note·지갑 로그는 공유하지 않습니다. 로컬 uclair 지급 성공을 Maroo 테스트넷 Privacy 성공으로 표현하지 마세요.

## 결과를 설명해 보세요

1. status 0인데도 이번 실험이 성공했다고 판단하는 이유는 무엇인가요?
2. 승인 취소를 체인에 어떻게 반영했고, 추가 지급이 없다는 것을 무엇으로 확인했나요?
3. 지급액과 실패 거래의 가스비는 어떻게 다른가요?
4. 로컬 Privacy 결과만으로 Maroo 호환성을 주장할 수 없는 이유는 무엇인가요?

조직의 PoC로 확장할 때는 신뢰할 발급자 제한, 지급 요청 중복 처리와 대사, Maroo 호환 증명 자료, 감사 권한과 키 보관 책임을 추가로 확인해야 합니다. 이 항목들은 이번 실습에서 완료한 기능이 아닙니다.
